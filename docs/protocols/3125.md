# Proto 3125 - Cofre VIP (estado)

## Descripción

El servidor envía `Proto=3125` con el estado del **Cofre VIP**: qué ranuras ya se reclamaron (máscara de bits) y el timestamp del último reclamo.

Es un paquete de **servidor → cliente** (respuesta a `3126` o notificación de estado).

## Wire

| Proto | Wire | Cifrado |
|-------|------|---------|
| 3125 | `0x0C35` | plano |

## Payload

| Offset | Tamaño | Campo | Descripción |
|--------|--------|-------|-------------|
| 0-1 | 2 (`uint16` LE) | mask | Máscara de bits: cada bit indica si la ranura `i` fue reclamada (1=reclamada, 0=disponible) |
| 2-5 | 4 (`uint32` LE) | lastClaimTimestamp | Timestamp Unix del último reclamo exitoso |
| 6+ | restante | desconocido | Datos adicionales sin decodificar |

## Máscara de bits

Cada bit del campo `mask` representa una ranura (índice 0-9):

| Bit | Índice | Significado |
|-----|--------|-------------|
| 0 | 0 | Ranura 0 reclamada |
| 1 | 1 | Ranura 1 reclamada |
| 2 | 2 | Ranura 2 reclamada |
| ... | ... | ... |
| 9 | 9 | Ranura 9 reclamada |

- `0` = ranura **disponible** para reclamar
- `1` = ranura ya **reclamada**

El bot calcula `nextIndex` buscando el primer bit en 0 (primera ranura libre).

## Ejemplo

```
body = 03 00 00 00 90 99 c8 ae 35 ...
```

| Campo | Bytes | Valor |
|-------|-------|-------|
| mask | `03 00` | `0x0003` = bits 0 y 1 → ranuras 0 y 1 reclamadas |
| lastClaimTimestamp | `00 00 00 00` | 0 (sin reclamos previos o.epoch) |
| nextIndex | calculado | 2 (primera ranura libre) |

## Relación con 3126

| Proto | Dirección | Uso |
|-------|-----------|-----|
| `3126` | Cliente → Servidor | Reclamar cofre VIP (envía índice de ranura) |
| `3125` | Servidor → Cliente | Estado actualizado (máscara + timestamp) |

**Flujo:**
1. Servidor envía `3125` con el estado actual
2. Bot busca primer bit libre en `mask` → obtiene `nextIndex`
3. Si `nextIndex != -1` y `Date.now() >= nextClaim * 1000`, envía `3126` con ese índice
4. Servidor reclama y envía nuevo `3125` con el bit actualizado

## Uso en el bot

- En `bot-instance.ts`, al recibir `3125` se parsea con `parseVipChest()` (`models/vip-chest-memory.ts`)
- Se guarda en `bot.vipChestMem`
- La acción `ChestVipAction` (`bot-action.ts`) verifica:
  - `nextIndex != -1` (hay ranuras libres)
  - `Date.now() >= nextClaim * 1000` (pasó la hora de cooldown)
- Si ambas condiciones se cumplen, envía `3126` con el índice
- After claim, actualiza localmente: `mask |= (1 << idx)`, `nextClaim = now + 3600`

## Cooldown

- Cada ranura tiene cooldown de **1 hora** después de reclamar
- Todas las ranuras se reinician diariamente al reinicio de la cuenta del servidor
