# Proto 3208 — Investigación completada (S→C)

Evento corto que llega cuando termina una investigación: indica qué tech subió
y a qué nivel. Es el mismo par de campos que la cabecera del [`3201`](3201.md)
(`u16 techId` + `u8 nivel`), sin timestamp ni restantes.

Tamaño del body: **3 bytes**.

```
offset  tamaño  campo
------  ------  ---------------------------
 0        2     u16 LE  TechID
 2        1     u8      nuevo nivel alcanzado
```

## Comportamiento verificado

En los 8 eventos presentes en los logs, el nivel informado por `3208` era
**exactamente el nivel de la cola del último `3201` + 1**:

```
3208: techId=298 nivel=9   ←   tail del 3201 previo: tech298 = 8
```

Es decir: **evento de finalización** (no de inicio). Al recibirlo hay que
sobrescribir `techLevels[techId - 1] = nivel`.

## Implementación (bot)

- Handler: `backend/src/bot/handlers/research-event.handler.ts`
  (`handleResearchEvent`) → actualiza `bot.research.techLevels`, log
  `[INVESTIGANDO]`/nivel completado y emite `researchUpdated` → evento socket
  `research`.
- Registro: `backend/src/bot/handlers/index.ts` (`3208: handleResearchEvent`).
- Tope de resistencia: el tech **153 "Límite de Resistencia"** (efecto 347
  `Máxima RES +`, +3/+6/…/+60) sube el máximo. Tras cada `3208`/`3201`,
  `bot.refreshResistenciaMax()` recalcula `120 + bonus`
  (`backend/src/bot/resistencia.ts`), lo expone como `resistenciaMax` en
  `playerInfo` y rearma el regenerador de resistencia si estaba llena al tope
  anterior.
- Prueba: `backend/scripts/test-resistencia.ts`.
- Prueba: `backend/scripts/test-parse-3201.ts` sección *3208 (evento de
  investigación)*.
