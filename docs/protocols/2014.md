# Análisis del Protocolo 2014 (Estado de Recursos)

## Resumen

El protocolo **2014** sincroniza el estado de los cinco recursos básicos del jugador.

Cada registro contiene dos datos fundamentales para un recurso:

* **Cantidad actual almacenada.**
* **Producción por hora.**

Los recursos aparecen siempre en el mismo orden:

1. Trigo
2. Piedra
3. Madera
4. Mineral
5. Oro

No se incluyen identificadores de recurso dentro del paquete, ya que el cliente conoce el orden fijo en que son enviados.

---

# Estructura del paquete

Después de la cabecera, el cuerpo está compuesto por **cinco registros consecutivos**, uno para cada recurso.

Cada registro ocupa **12 bytes**.

| Campo               |  Tamaño | Tipo   | Descripción                                            |
| ------------------- | ------: | ------ | ------------------------------------------------------ |
| Cantidad            | 4 bytes | UInt32 | Cantidad actual del recurso almacenado por el jugador. |
| Producción por hora | 8 bytes | UInt64 | Producción total del recurso por hora.                 |

---

# Estructura de un registro

| Offset |  Tamaño | Tipo   | Descripción                            |
| -----: | ------: | ------ | -------------------------------------- |
|   0x00 | 4 bytes | UInt32 | Cantidad almacenada del recurso.       |
|   0x04 | 8 bytes | UInt64 | Producción total por hora del recurso. |

---

# Orden de los registros

El protocolo no necesita indicar qué recurso representa cada entrada, ya que siempre mantiene el mismo orden.

| Posición | Recurso |
| -------- | ------- |
| 1        | Trigo   |
| 2        | Piedra  |
| 3        | Madera  |
| 4        | Mineral |
| 5        | Oro     |

---

# Observaciones

Durante las capturas se comprobó que:

* Cada recurso ocupa exactamente **12 bytes**.
* El primer valor corresponde a la **cantidad actual** disponible.
* El segundo valor corresponde a la **producción total por hora** calculada por el servidor.
* Ambos valores son independientes: la cantidad cambia al obtener o gastar recursos, mientras que la producción cambia al modificar edificios, investigaciones, talentos, equipamiento o bonificaciones.

---

# Características

| Característica          | Valor    |
| ----------------------- | -------- |
| Proto                   | 2014     |
| Recursos sincronizados  | 5        |
| Tamaño de cada registro | 12 bytes |
| Cantidad                | UInt32   |
| Producción por hora     | UInt64   |

---

# Flujo del protocolo

1. El servidor calcula la cantidad actual de cada recurso.
2. Calcula la producción por hora aplicando todos los modificadores activos.
3. Genera un registro para cada uno de los cinco recursos.
4. Envía el paquete `Proto 2014`.
5. El cliente actualiza la interfaz mostrando tanto la cantidad disponible como la producción por hora correspondiente.

---

# Conclusión

El protocolo **2014** sincroniza el estado económico básico del jugador. Cada registro contiene la **cantidad almacenada** y la **producción por hora** de uno de los cinco recursos principales del juego. Gracias al orden fijo de los registros, no es necesario transmitir un identificador para cada recurso, reduciendo el tamaño del paquete y simplificando su procesamiento por parte del cliente.
