# Proto 9864 - Canjear dígitos por gems (LUCKYCARD_EXCHANGE)

## Descripción

Comando **cliente → servidor**: canjea los dígitos que tiene la cuenta en mano
por el número de gems que muestra el evento. El canje se puede hacer **una sola
vez por evento** (regla del evento "Lucky Cards"), así que el bot sólo lo manda
cuando tiene **tres nueves** en la mano y ya no vuelve a buscar cofres en ese
evento.

Nombres del cliente de referencia: `_MSG_REQUEST_LUCKYCARD_EXCHANGE`
(`Protocol.cs:1714`) y
`LuckyCardShopData.Send_MSG_REQUEST_LUCKYCARD_EXCHANGE(uint Exchange)`
(`docs/Cosas de otro bot/LordsMobileBot/LuckyCardShopData.cs:159`).

## Wire

| Proto | Wire | Cifrado |
|-------|------|---------|
| 9864 | `0x2688` | Sí — DES / ECB (con seq) |

El engine prepende los 4 bytes de seq con
`sendCommandPacket(9864, payload, true)` → `MessagePacket` → cifrado en bloques
de 8 bytes (`game-client.ts:114`). El paquete completo mide 12 bytes:
`len(2) + proto(2) + seq(4) + u32(4)` → header `0c008826`.

## Payload (4 bytes, excluyendo el seq)

| Offset | Tamaño | Campo | Descripción |
|--------|--------|-------|-------------|
| 0-3 | 4 | value | u32 LE: **número a canjear** (los 3 dígitos más altos en mano, en orden descendente) |

## Ejemplos reales (capturas del cliente)

| plain (8 B) | seq | value |
|-------------|-----|-------|
| `180100004b030000` | 280 | **843** |
| `30000000da030000` | 48 | **986** |
| `3700000083020000` | 55 | **643** |

Los tres valores son los **3 dígitos más altos en orden descendente** de la mano
en ese momento (8-4-3, 9-8-6, 6-4-3). Con tres nueves en mano, el valor es
**999**.

```
plain: 18010000 4b030000
       └ seq 4B ┘└ u32 LE = 843 ┘
enc (DES/ECB, 8 B cada uno): 63f9f9357f579d02, 25b6f2a5f5ba05d9
   (formas cifradas vistas en la misma captura; el emparejamiento con su
    body en claro no se conservó)
```

## Respuesta

El servidor contesta con [`9865`](9865.md) (body de 10 bytes: status + eco del
número + saldo de gems).

## Uso en el bot

```typescript
// backend/src/bot/commands/lucky-card.commands.ts
exchangeLuckyCards(bot, value);   // 4 bytes u32 LE + seq

// backend/src/bot/core/bot-instance.ts
runLuckyCardStep()                // si luckyHasExchangeDigits() → runLuckyExchangeStep()
runLuckyExchangeStep()            // reintenta a los 60 s, máx 3 intentos, timeout 15 s
sendLuckyExchange()               // loguea [CARTA] 9864 → canjear 999 (3 nueve(s))
```

- El envío que **falla** (el paquete no llega a salir) **no** cuenta como
  intento: se reintenta.
- Cada envío registra `luckyExchangeEventKey = luckyEventKey`; un `9865` sólo se
  acepta si coincide con el evento vigente.
- Al agotar los 3 intentos sin `9865` se cierra el evento en la DB con
  `status = -1` (ya no se reintenta ni en ese evento ni tras un reinicio).

Constantes: `LUCKY_EXCHANGE_MIN_NINES = 3`, `LUCKY_EXCHANGE_TIMEOUT_MS = 15_000`,
`LUCKY_EXCHANGE_RETRY_MS = 60_000`, `LUCKY_EXCHANGE_MAX_ATTEMPTS = 3`
(`bot-instance.ts:97-103`).

## Notas

- El número **no** es la recompensa sino lo que se canjea; la recompensa en gems
  no se observó en el `9865` (sólo el saldo total).
- Mientras el canje está pendiente el bot **no consulta cofres**: el modo canje
  no usa el slot de búsqueda.
- El valor se arma localmente con `luckyExchangeValue()` (top-3 descendente); si
  el servidor devolviera un eco distinto en el `9865` se loguea un warning pero
  se acepta el canje igual (status 0).
- Todavía no se observó un 9864 real disparado por el bot (el trigger de tres
  nueves no se dio en vivo todavía).
