# Proto 3610 - Recompensas por nivel (Quest/Reward)

## Descripción

El servidor envía `Proto=3610` con información de recompensas organizadas por niveles. Contiene tipo de evento, ID de misión, datos de tres niveles (gemas + valor en gemas + items sin valorar), contadores de registros por nivel, y una lista de recompensas individuales (item ID + cantidad).

> **Estado:** Estructura confirmada.

## Wire

| Proto | Wire | Cifrado |
|-------|------|---------|
| 3610 | — | Plano |

---

## Estructura general

```
[tipo de evento] (2 bytes)
[ID de misión] (12 bytes)
[datos nivel 1] (10 bytes)
[datos nivel 2] (10 bytes)
[datos nivel 3] (10 bytes)
[cantidades de registros] (4 bytes)
[lista de recompensas...]
```

---

## Cabecera (14 bytes)

| Offset | Tamaño | Campo | Descripción |
|--------|--------|-------|-------------|
| 0-1 | 2 | tipoEvento | Tipo de evento (uint16 LE) |
| 2-13 | 12 | missionId | ID de la misión (12 bytes) |

### Ejemplo

```
00 01          → tipo de evento = 1
09 01 00 00 00 00 00 00 00 00 00 00  → mission ID
```

---

## Datos por nivel (10 bytes c/u)

Cada nivel tiene exactamente la misma estructura:

| Offset | Tamaño | Campo | Descripción |
|--------|--------|-------|-------------|
| 0-1 | 2 | gems_entrega | Gemas fisicas que recibes en tu cuenta al completar el nivel (uint16 LE) |
| 2-3 | 2 | separador | Separador (siempre `00 00`) |
| 4-7 | 4 | valorGemas | Valor equivalente en gemas de los items del nivel (uint32 LE) |
| 8 | 1 | sinValorar | Cantidad de items sin valorar (uint8) |
| 9 | 1 | fin | Fin del paquete del nivel (siempre `00`) |

### Diferencia entre gems_entrega y valorGemas

- **gems_entrega**: son las gemas que recibes fisicamente en tu cuenta. Si completas el nivel, te ingresan esas gemas directamente.
- **valorGemas**: es el valor equivalente en gemas de los items que contiene el nivel. No son gemas que recibes, sino una referencia de cuánto valen los items en gemas. Por ejemplo, si un nivel tiene `valorGemas=2916` y sus items, completar ese nivel equivale a recibir items por un valor total de 2916 gemas.

### Ejemplo nivel 1

```
00 00    → gems_entrega = 0
00 00    → separador
16 04 00 00 → valorGemas = 0x00000416 = 1046
03       → sinValorar = 3
00       → fin del nivel
```

### Ejemplo nivel 2

```
00 00    → gems_entrega = 0
00 00    → separador
64 0b 00 00 → valorGemas = 0x00000b64 = 2916
04       → sinValorar = 4
00       → fin del nivel
```

### Ejemplo nivel 3

```
84 03    → gems_entrega = 0x0384 = 900
00 00    → separador
6c 1b 00 00 → valorGemas = 0x00001b6c = 7020
0b       → sinValorar = 11 (0x0B en hex)
00       → fin del nivel
```

### Resultado

| Nivel | Gems fisicas | Valor equiv. en gemas | Sin valorar |
|-------|-------------|----------------------|-------------|
| 1     | 0           | 1046                 | 3           |
| 2     | 0           | 2916                 | 4           |
| 3     | 900         | 7020                 | 11          |

---

## Cantidades de registros (4 bytes)

Después de los tres niveles aparecen 4 bytes:

| Offset | Tamaño | Campo | Descripción |
|--------|--------|-------|-------------|
| 0 | 1 | countN1 | Cantidad TOTAL de registros del nivel 1 (uint8) |
| 1 | 1 | countN2 | Cantidad TOTAL de registros del nivel 2 (uint8) |
| 2 | 1 | countN3 | Cantidad TOTAL de registros del nivel 3 (uint8) |
| 3 | 1 | separador | Separador (siempre `00`) |

> **IMPORTANTE:** Estos valores determinan cuántos registros de 4 bytes consecutivos pertenecen a cada nivel. NO deben confundirse con los campos `sinValorar` de cada nivel.

### Ejemplo

```
04 08 0b 00
```

- `04` → 4 registros del nivel 1
- `08` → 8 registros del nivel 2
- `0b` → 13 registros del nivel 3 (0x0B en hex)
- `00` → separador

Total: 4 + 8 + 13 = 25 registros → 25 × 4 = 100 bytes

---

## Lista de recompensas

Después del separador `00` comienza la lista de registros.

Cada registro ocupa exactamente **4 bytes**:

| Offset | Tamaño | Campo | Descripción |
|--------|--------|-------|-------------|
| 0-1 | 2 | itemId | ID del item (uint16 LE) |
| 2 | 1 | cantidad | Cantidad del item (uint8) |
| 3 | 1 | campo | Separador / campo adicional (uint8) |

### Regla fundamental

Los registros se asignan a cada nivel por **posición**, NO por el valor del byte `cantidad`:

```
countN1 registros → NIVEL 1
countN2 registros → NIVEL 2
countN3 registros → NIVEL 3
```

El byte `cantidad` de cada registro es la cantidad de ese item, NO indica el nivel.

### Ejemplo

```
e507 01 00    → ID 0x07E5 (2021), cantidad 1, campo 0 → NIVEL 1
7d04 01 00    → ID 0x047D (1149), cantidad 1, campo 0 → NIVEL 1
0305 02 00    → ID 0x0503 (1283), cantidad 2, campo 0 → NIVEL 1
5904 01 00    → ID 0x0459 (1113), cantidad 1, campo 0 → NIVEL 1
e507 02 00    → ID 0x07E5 (2021), cantidad 2, campo 0 → NIVEL 2
...
```
