# Proto 2452 - Enviar caravana de recursos (supply)

## Descripción

El cliente envía `Proto=2452` para enviar una caravana de recursos a otra ubicación del mapa. Cada caravana lleva un tipo de recurso con hasta la capacidad por caravana, que sale del stat `Capacidad de suministro +` de la cuenta (antes era `maxAmount`, un valor fijo de config). El servidor responde con `2453` por cada caravana (≥17B = salió, <17B = fallo, ver [`2453`](2453.md)) y `2455` cuando el lote completo finaliza.

## Wire

| Proto | Wire | Cifrado |
|-------|------|---------|
| 2452 | — | Plano |

## Payload (23 bytes)

| Offset | Tamaño | Campo | Descripción |
|--------|--------|-------|-------------|
| 0-2 | 3 | coord | Coordenada destino codificada en 3 bytes |
| 3-6 | 4 | wheat | Cantidad de trigo (uint32 LE, 0 si no envía este recurso) |
| 7-10 | 4 | stone | Cantidad de piedra (uint32 LE, 0 si no envía) |
| 11-14 | 4 | wood | Cantidad de madera (uint32 LE, 0 si no envía) |
| 15-18 | 4 | mineral | Cantidad de mineral (uint32 LE, 0 si no envía) |
| 19-22 | 4 | gold | Cantidad de oro (uint32 LE, 0 si no envía) |

Solo uno de los campos de recurso tendrá valor; el resto serán `00000000`.

## Respuestas del servidor

| Proto | Descripción |
|-------|-------------|
| `2453` | Respuesta individual: ≥17B caravana en marcha / <17B **fallo** (nada salió) |
| `2455` | Lote completado — todas las caravanas del batch procesadas |

## Secuencia completa

```
Una vez (al iniciar el lote):
  1109 → 1110 (buscar perfil)
  2204 → 2205 (obtener ubicación)
  2201 (abrir mapa alrededor del target)
  Chequeo de gremio: tile 0x08 tag vs bot.guildTag (2802)

Por cada caravana (bucle hasta vaciar la cola):
  Esperar slot libre: marchas IDA 2220 activas < caravanLimit
    (slot se libera en startTime + 2×duration)
  2202 (seleccionar castillo)
  2452 → 2453 (enviar caravana; 2453 corto = fallo → reintentar hasta 3 veces)
  Esperar 2220 de la marcha (o slot ghost 10min)

2455: lote completado (residual; el bucle no depende de él)
```

**Importante**: Antes de cada 2452 se debe enviar 2202 con la misma coordenada, con el mapa ya abierto vía 2201. Sin esto, el servidor desconecta al cliente. Además, entre **2201 → 2202 → 2452** debe haber un **cooldown de ≥1 s** (`waitMapProtoCooldown()`): si van pegados el 2453 responde `0e` (rate limit) y no sale nada.

## Código fuente

- **`sendNextCaravan()`** en `backend/src/bot/core/bot-instance.ts` — construye y envía el payload
- **`sendCaravanBatch()`** en `backend/src/bot/core/bot-instance.ts` — 2201 + chequeo gremio + bucle 2202/2452 con slots
- **Handler 2455**: `handleCaravanComplete` en `backend/src/bot/handlers/supply.handler.ts`

## Ejemplo

```
Coordenada destino: 16 02 ff
Recurso: trigo, cantidad: 6,000,000 (0x005B8D80)

Payload hex:
  1602ff 808d5b00 00000000 00000000 00000000 00000000
  coord   wheat    stone    wood     mineral   gold
```

## Configuración

```json
{
  "supply": {
    "enable": false,
    "targetPlayer": "NombreJugador",
    "threshold": 7000000,
    "caravanLimit": 4
  }
}
```

- `threshold`: mínimo de recurso para activar envío
- capacidad por caravana: **no es config**; sale del stat `Capacidad de suministro +` (`getSupplyCapacity()`)
- `caravanLimit`: máximo de **marchas IDA simultáneas** (slots); cada 2452 cuenta un slot hasta `startTime + 2×duration`
