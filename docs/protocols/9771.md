# Proto 9771 — Lista de artefactos poseídos (S→C)

Push de login: el servidor manda **todos** los artefactos de la cuenta con su
nivel y estrellas. **No hay request previo** (llega solo, ~RECV #110-#115 de
cada sesión, antes que muchos otros pushes). En los logs se ve como
`[RECV #114] Proto=9771 Len=162 header=a2002b26 …`.

- Wire proto: `0x262B` (**igual** al proto lógico, sin traducción).
- Cifrado: **PLANO** (el body va en claro; sólo el 3010 se descifra).

## Body

| offset | tamaño | campo |
| ------ | ------ | ----- |
| 0      | 2      | u16 LE — `count` (138 máx. observado; safety del parser: `count > 300` → null) |
| 2      | `count × 4` | un registro por artefacto poseído |

Registro de 4 bytes:

| offset | tamaño | campo |
| ------ | ------ | ----- |
| 0      | 2      | u16 LE — `artifactId` (items 7001..7250, claves de `RelicsUpgrade`) |
| 2      | 1      | u8 — nivel (1..12; máx. observado en logs: 9) |
| 3      | 1      | u8 — estrellas (0..6; **6 = Bendecido**) |

**Ancla de la composición**: `body.length == 2 + count * 4` se cumple
exactamente en todas las capturas (se validó contra 26 cuentas distintas con
niveles 1..9 y estrellas 0..6). El parser rechaza (`null`) cualquier body que
no respete el ancla, tenga `level > 12`, `star > 6` o `count > 300`.

## Comportamiento verificado

- **Cuenta nueva** (2011305644): `count = 39`, los 39 artefactos en
  `nv1 / ★0` → confirma el orden de los campos (nivel antes que estrellas) y
  que el server manda el inventario completo, no solo cambios.
- **Cuenta 858715903** (fixture de los tests): `count = 138`, niveles 3..9,
  estrellas 0..6 incluyendo 7051 `nv8 ★6` (Bendecido) y las 3 piezas de los 3
  sets.
- El mismo cuerpo se repite en varios envíos de la misma sesión (cada
  re-login/re-conexión lo vuelve a mandar).
- Los ids saltan (p. ej. el fixture tiene 7053..7069 casi todos ausentes):
  los artefactos no poseídos simplemente no aparecen en la lista.

## Tablas del cliente (Table.unity3d)

Ver [`docs/investigacion/artefactos.md`](../investigacion/artefactos.md) para
el decode completo de las 5 tablas (`Item`, `RelicsUpgrade`,
`RelicsCombination`, `RelicsEnhance`, `Effect`). Resumen:

- **244 artefactos** (7001..7250): 39 Extraordinario / 105 Épico /
  100 Legendario.
- **12 niveles** por artefacto: los valores de `RelicsUpgrade` son **totales
  acumulados** (no deltas) y el coste es "para subir de ESTE nivel" (0 en
  nv12).
- **Estrellas**: `RelicsEnhance` da el multiplicador en centésimas —
  `×1.0 / 1.1 / 1.2 / 1.3 / 1.4 / 1.5` (★0..★5) y `×2.0` (★6 Bendecido),
  igual para los 3 grados. El múltiplo se aplica **después** del total del
  nivel: `round(value * mult / 10000)`.
- **3 sets** (`RelicsCombination`): bonus por tier que se **acumulan**
  (coleccionar → ★3+ → Bendecido).

## Implementación (bot)

- Parser: `backend/src/bot/parsers/artifacts.parser.ts` (`parse9771`).
- Handler: `backend/src/bot/handlers/artifact.handler.ts` (`handle9771`) →
  guarda `bot.artifacts`, recalcula `playerStats`, log
  `[ARTEFACTOS] 9771: …` (sólo al primer envío o si cambia algo) y emite
  `artifactsUpdated` → evento socket `artifacts`.
- Registro: `backend/src/bot/handlers/index.ts` (`9771: handle9771`).
- Catálogo: `backend/src/bot/data/artifacts-db.ts`
  (`ARTIFACT_DEFS`, `ARTIFACT_SETS`, `buildArtifactViews`, `buildSetViews`,
  `applyStarMultiplier`).
- Stats: `backend/src/bot/artifact-stats.ts` (`computeArtifactStats`) +
  fuente `artifact` / "Artefactos" en
  `backend/src/bot/features/player-stats.ts` (fusiona con research/talentos
  porque comparten `key = nombre|unidad`).
- Payload: `getBotData` manda `artifacts` (vistas) y el push `artifacts`
  incluye `playerStats` actualizado.
- UI: `frontend/src/components/BotDetail.tsx`, pestaña *Artefactos* —
  listado con grado/nivel/estrella/efectos + sección de sets con tiers.
- Prueba: `backend/scripts/test-artifacts.ts` (68 checks; fixture = body real
  de esta cuenta).
