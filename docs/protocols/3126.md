# Proto 3126 - Reclamar cofre VIP

## Descripción

Proto de 5 bytes: 4 bytes u32 (little-endian) + 1 byte de índice (ranura a reclamar).

El cliente lo envía cuando `ChestVipAction` detecta una ranura libre y pasó el cooldown.
La respuesta es un `3125` (ver `3125.md`).

## Wire

| Proto | Wire | Cifrado |
|-------|------|---------|
| 3126 | `0x0C36` | plano |

## Payload

```
plain = [u32 seq] [u8 index]
```

`seq` = `globalSeq` del cliente (contador incremental que `sendCommandPacket()` prepende
cuando `includeSeq = true`, ver `engine/bot-engine.ts`). `index` = ranura a reclamar.

### Ejemplos

| plain                | seq  | index |
|----------------------|------|-------|
| `0f 00 00 00 00`     | 15   | 0     |
| `13 00 00 00 01`     | 19   | 1     |
| `16 00 00 00 02`     | 22   | 2     |
| `32 00 00 00 00`     | 50   | 0     |
| `4e 00 00 00 02`     | 78   | 2     |

## Respuesta (`3125`)

| Respuesta | Significado |
|-----------|-------------|
| `00 <mask> <ts4> …` | Éxito: estado nuevo con la ranura marcada como reclamada |
| `03 00 00 00 …` | **Rechazado**: la ranura ya estaba reclamada (o no disponible aún) |

Ver `3125.md` para el layout completo de cada variante.

## Comportamiento

- Cada ranura se recarga 1 hora después de reclamar (`VIP_CHEST_COOLDOWN = 3600`)
- Se reinician diariamente al reinicio de la cuenta
- Índices observados en los logs: 0 y 2 (documentación previa: 0-5; el parser asume 10 ranuras)
- El bot marca localmente la ranura al enviar (`mask |= 1 << idx`) para no repetir el
  reclamo si la respuesta es un rechazo

## Pendientes de decodificar

- Número real de ranuras (observadas 0-2; esta doc decía 0-5; el parser asume 10)
