# Proto 1417 — Lista de Trajes (Lord Equipment)

## Nombre interno
`_MSG_RESP_LORDEQUIP`

## Dirección
IN (servidor → cliente)

## Descripción
Contiene la lista completa de trajes (Lord Equipment) que posee el jugador. Cada traje incluye su ID, nivel de calidad (grade), estado de gemas y nivel de sigilo.

## Solicitud
El servidor envía este paquete como respuesta a:
- Proto **1416** (`_MSG_REQUEST_LOADEQUIP`) — solicitado al cargar datos del jugador
- Eventualmente al abrir la pantalla de trajes en el juego

## Múltiples paquetes
El servidor puede enviar **1 a 3 paquetes 1417** en secuencia. Cuando hay más de 1, son fragmentos de la lista completa. Se deben **acumular y deduplicar por ID**.

### Tipos de paquete

| Primer byte | Significado | Cómo parsear |
|-------------|-------------|--------------|
| `00`        | Paquete con header completo | Parsear header (13 bytes) + items |
| `02`        | Continuación | Saltar el `02`, parsear items directamente (sin header) |

## Estructura general

```
+---------------------------+
| Header (13 bytes)         |  ← solo si empieza con 00
+---------------------------+
| Traje 1 (19 bytes)        |
+---------------------------+
| Traje 2 (19 bytes)        |
+---------------------------+
| ...                       |
+---------------------------+
| Traje N (19 bytes)        |
+---------------------------+
```

---

## Header (13 bytes)

Solo presente cuando el primer byte es `00`.

| Offset | Tamaño | Tipo     | Nombre              | Descripción |
|--------|--------|----------|---------------------|-------------|
| 0x00   | 1      | uint8    | start               | Byte de inicio (`00`) |
| 0x01   | 4      | uint32LE | timestamp           | Timestamp de la actualización |
| 0x05   | 4      | uint32LE | timestampSeparator  | Separador de timestamp |
| 0x09   | 2      | uint16LE | separator           | Separador |
| 0x0B   | 2      | uint16LE | count               | Cantidad de trajes en este paquete |

### Ejemplo de header
```
00 00000000 00000000 0000 2100
│  │         │         │     └─ count = 0x0021 = 33 trajes
│  │         │         └─────── separator
│  │         └───────────────── timestampSeparator = 0
│  └─────────────────────────── timestamp = 0
└────────────────────────────── start = 0x00
```

## Traje (19 bytes por entrada)

| Offset | Tamaño | Tipo     | Nombre         | Descripción |
|--------|--------|----------|----------------|-------------|
| 0x00   | 2      | uint16LE | id             | ID interno del traje |
| 0x02   | 1      | uint8    | grade          | Calidad/nivel del traje |
| 0x03   | 1      | uint8    | gemLevel1      | Nivel de la gema 1 |
| 0x04   | 1      | uint8    | gemLevel2      | Nivel de la gema 2 |
| 0x05   | 1      | uint8    | gemLevel3      | Nivel de la gema 3 |
| 0x06   | 1      | uint8    | stealthLevel1  | Nivel de sigilo 1 |
| 0x07   | 2      | uint16LE | gemId1         | ID de la gema 1 |
| 0x09   | 2      | uint16LE | gemId2         | ID de la gema 2 |
| 0x0B   | 2      | uint16LE | gemId3         | ID de la gema 3 |
| 0x0D   | 2      | uint16LE | stealthId1     | ID de sigilo 1 |
| 0x0F   | 2      | uint16LE | index          | Índice del traje en la lista |
| 0x11   | 2      | uint16LE | end            | Separador/fin (siempre `0000`) |

### Tamaño total por traje: **19 bytes**

## Ejemplo real parseado

### Paquete con header (primer byte `00`)
```
00                              ← start
00000000                        ← timestamp
00000000                        ← timestampSeparator
0000                            ← separator
2100                            ← count = 33

5b110500000000000000000000000001000000   ← traje #1
65110500000000000000000000000002000000   ← traje #2
3e110500000000000000000000000003000000   ← traje #3
...
98120200000000000000000000000021000000   ← traje #33
```

### Paquete de continuación (primer byte `02`)
```
02                              ← prefijo de continuación (se ignora)
5b110500000000000000000000000001000000   ← traje #1
65110500000000000000000000000002000000   ← traje #2
...
```

## Interpretación de campos

### id (2 bytes)
ID único del traje. Se usa para identificar el traje en otros protocolos (ej: proto 6102 para equiparlo).

### grade (1 byte)
Calidad/nivel del traje:

| Valor | Significado |
|-------|-------------|
| 0x01  | Común       |
| 0x02  | Poco común  |
| 0x03  | Raro        |
| 0x04  | Épico       |
| 0x05  | Legendario  |
| 0x06  | Mítico      |

### gemLevel1/2/3 (1 byte cada uno)
Nivel de cada gema insertada en el traje. `00` = sin gema.

### gemId1/2/3 (2 bytes cada uno)
ID de cada gema insertada. `0000` = vacío.

| Valor | Gema |
|-------|------|
| `6a10` | Gema roja |
| `6b10` | Gema azul |
| `6910` | Gema verde |

### stealthLevel1 (1 byte)
Nivel del componente de sigilo.

### stealthId1 (2 bytes)
ID del componente de sigilo. `0000` = sin sigilo.

### index (2 bytes)
Posición del traje en la lista del jugador. Comienza en 1.

### end (2 bytes)
Separador de fin. Siempre `0000`.

## Tamaño total del paquete

```
Con header:    13 + (count × 19) bytes
Sin header:    count × 19 bytes
```

## Parser implementado

**Archivo:** `backend/src/bot/parsers/costume.parser.ts`

```typescript
import { parseCostumePacket } from '../parsers/costume.parser';

// Auto-detecta header (00) o items-only (02)
const result = parseCostumePacket(body);
// result.hasHeader  → boolean
// result.items      → CostumeItem[]
// result.header     → CostumeHeader | null
```

- Detecta primer byte (`00` o `02`)
- Parsea items
- Deduplica por `id` contra `bot.costumes[]`
- Emite `costumesUpdated`

## Notas

- El parser auto-detecta si hay header basándose en: `(bytes - 13) % 19 === 0`
- Si no hay header, calcula la cantidad de trajes desde `floor(bytes / 19)`
- Los bytes sobrantes (incompletos) se ignoran
- Los IDs de traje son valores internos del juego, no decimales
