## Disclaimer

This document represents evidence-based reverse engineering. Fields are classified as:

- **KNOWN**: Meaning confirmed through observation and correlation.
- **UNKNOWN**: Present in the packet but meaning not determined.
- **HYPOTHESIS**: Preliminary interpretation not yet confirmed.

No field meaning is invented. If the purpose is unclear, it is documented as UNKNOWN.

## Open Questions

1. **What does `01420000` / `0d420000` (unknownPrefix1) represent?**
   Byte 0 varies (`01` vs `0d`). Could be packet subtype, protocol version, or attack type.

2. **What does `57005202e10801` (unknownPrefix2) represent?**
   Identical in both packets. Could be a session ID, map reference, or fixed protocol header.

3. **What is the structure of the 62-byte unknownBlock1?**
   Starts with `03` in both. Bytes 4-23 contain an identical pattern (`040005010005140005110005020004`). May encode troop configuration, hero data, or battle parameters.

4. **What do the trailing bytes after name null terminators represent?**
   P1 attacker: `135700`, P2 attacker: `5700`. P1 defender: `c5`, P2 defender: `9c`. Could be player ID, sub-realm, or hash.

5. **What is the internal structure of the 3-byte locations?**
   HYPOTHESIS: Could encode kingdom + map coordinates, or a location ID. The 3-byte size suggests uint24.

6. **Are the `00000000` separators truly separators?**
   Could be zero-valued metrics (e.g., troops of a specific type that weren't used).

7. **What do the level-adjacent fields represent?**
   `unknownLevelField3` (`200001`) is identical in both packets — could be a constant or a version marker.

8. **What is the 181-byte unknownFinalBlock?**
   HYPOTHESIS: Likely contains troop type composition for both sides. P1 ends with pattern `150017001b0029002a000a0a0a0504050003...` resembling arrays of uint16 troop counts.

9. **Why does unknownBlock2 contain non-zero values in P2?**
   P2 has `27000000 27000000` where P1 is all zeros. May relate to battle modifiers or troop types.

## Parser Usage

```javascript
const { parse } = require('./parser/attack-parser');

const result = parse('0142000000eea7aa6a00000000...');

// Access known fields
console.log(result.timestamp.value);          // 1789569006
console.log(result.attacker.kingdom);          // 1332
console.log(result.attacker.name);             // "AKIIATbIR"
console.log(result.levels.attackerLevel);      // 60

// Access raw unknown fields
console.log(result.unknownBlock1);             // "03000000..."
console.log(result.unknownFinalBlock);         // "01140000..."

// Byte reconstruction (verify no bytes lost)
const r = result.raw;
const reconstructed =
  r.unknownPrefix1 + r.separator1 + r.timestamp +
  r.separator2 + r.unknownPrefix2 +
  r.attackerKingdom + r.enemyGuildTag + r.attackerNameRaw +
  r.defenderKingdom + r.myGuildTag + r.defenderNameRaw +
  r.unknownBlock1 +
  r.enemyLocation + r.enemyPowerLost + r.separator3 +
  r.enemyTroopsSent + r.enemyTroopsDefeated + r.separator4 +
  r.myLocation + r.myPowerLost + r.separator5 +
  r.myTotalTroops + r.myTroopsDefeated +
  r.unknownBlock2 +
  r.attackerLevel + r.unknownLevelField1 +
  r.attackerVipLevel + r.unknownLevelField2 +
```
