# Proto 5201 - Coliseo (estado / lista de rivales)

## Descripción

El servidor envía `Proto=5201` con el estado del **Coliseo**: puesto del jugador, cuántas veces peleó (máximo 5), gemas disponibles para reclamar y la lista de rivales (nombre, tag de gremio y bloque de héroes).

Es un paquete de **servidor → cliente** (notificación de estado).

## Wire

| Proto | Wire | Cifrado |
|-------|------|---------|
| 5201 | `0x1451` | plano |

## Payload (cabecera)

| Offset | Tamaño | Campo | Descripción |
|--------|--------|-------|-------------|
| 0-3 | 4 (`uint32` LE) | puesto | Posición del jugador en el Coliseo |
| 4-13 | 10 | desconocido | 5 × `uint16` (¿puestos / ids?) — sin decodificar |
| 14-15 | 2 (`uint16` LE) | peleas | Cantidad de veces peleadas (máx **5**; el ejemplo trae `04 00` = 4/5) |
| 16-19 | 4 (`uint32` LE) | desconocido | Sin decodificar |
| 20-23 | 4 (`uint32` LE) | desconocido | Sin decodificar |
| 24-27 | 4 (`uint32` LE) | gemas | Gemas disponibles para reclamar |
| 28-29 | 2 (`uint16` LE) | desconocido | Sin decodificar |

## Payload (rivales, desde offset 30)

Luego vienen entradas repetidas, una por rival:

| Campo | Tamaño | Descripción |
|-------|--------|-------------|
| nombre | ASCII hasta `00` (padding nulo) | Nombre del rival |
| tag de gremio | 3 bytes ASCII | Tag del gremio |
| bloque héroe | 36 bytes | `heroId` (4, `uint32` LE) + 16 × `uint16` (datos de héroes, sin decodificar) |

|-------|-------|

| peleas | `0400` → 4 (de 5) |
| gemas | `f20a0000` → 2794 |

| rival 3 | `Guard.1704` — tag `000` — heroId `8f090000` (2447) |

> La cola final (a partir de `125095...`) no está decodificada.

## Semántica de `fightsDone` y reinicio

- El campo `fightsDone` (offset 14) cuenta las **peleas ya hechas**: `0000` = ninguna hecha = las 5 disponibles.
- El juego lo muestra **invertido**: pinta "5/5" y va restando hasta "0/5". Es el complemento: disponibles = `5 - fightsDone`.
- Disponibles = `5 - fightsDone`. Con `0000` hay 5 libres; con `0500` no queda ninguna.

### Reinicio

El contador **lo reinicia el servidor del juego**, no el bot ni el reinicio de la cuenta:

- Se resetea cada día a las **00:00 UTC / 02:00 ARG**.
- Al volver la cuenta a la normalidad no se reinicia; solo cambia cuando el servidor pone `fightsDone` en `0000`.
- El bot no hace nada para resetear: cuando el servidor envía el `5201` con `0000`, `bot.coliseumState` se actualiza solo y se emite el evento `coliseum`.

> El 5201 se recibe de forma espontánea (servidor → cliente), no hace falta pedirlo.

## Uso en el bot

- Al recibir `5201`, se parsea con `parseColiseum()` (`backend/src/models/coliseum.ts`) y se guarda en `bot.coliseumState`.
- Se emite por socket como evento `coliseum` y se incluye en `getBotData` → lo muestran la web y la app.
- Con las peleas (`fightsDone`) se puede saber cuándo el Coliseo quedó libre (0/5 → hay peleas disponibles).
- Si `config.coliseum.reclaimGems = true` y `gems > 0`, se envía automáticamente [`5214`](5214.md) para reclamar las gemas.
