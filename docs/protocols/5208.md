# Proto 5208 - Coliseo (atacar rival)

## Descripción

El cliente envía `Proto=5208` para atacar un rival en el Coliseo. Contiene el index del rival, su ID, el nombre del atacante y los 5 héroes seleccionados.

## Wire

| Proto | Wire | Cifrado |
|-------|------|---------|
| 5208 | `0x1458` | Sí |

## Payload (28 bytes, excluyendo seq)

El engine agrega 4 bytes de seq al inicio automáticamente via `sendCommandPacket`.

| Offset | Tamaño | Campo | Descripción |
|--------|--------|-------|-------------|
| 0 | 1 | index | Posición del rival en la lista (0, 1, 2...) |
| 1-4 | 4 (`uint32` LE) | rivalId | ID del rival (viene del proto 5205) |
| 5-17 | 13 | nombre | Nombre del rival (ASCII, padding con `00`) — viene del proto 5205 |
| 18-27 | 10 | heroes | 5 × heroId (`uint16` LE) — héroes seleccionados |

## Ejemplo

```
5208 plain (body, incluyendo seq):
seq:    71 01 00 00
index:  00                          ← rival 0
rival:  3f 0b 00 00                  ← ID 2879 (uint32 LE)
name:   47 75 61 72 64 2e 31 39 36 33 00 00 00  ← "Guard.1963" + padding
heroes: 01 00 03 00 06 00 05 00 17 00  ← [1, 3, 6, 5, 23]
```

## Relación con5205

Para atacar, primero se piden los rivales con [`5204`](5204.md), se recibe [`5205`](5205.md) con la lista, y luego se envía `5208` usando:
- `index` = posición en la lista (0-based)
- `rivalId` = el ID que viene en el bloque de cada rival del 5205

## Uso en el bot

```typescript
bot.attackColiseumRival(rivalIndex, rivalId, rivalName, [hero1, hero2, hero3, hero4, hero5]);
```
