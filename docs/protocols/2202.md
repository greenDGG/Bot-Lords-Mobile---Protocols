# Proto 2202 - Consultar información de tile

## Descripción

El cliente envía `Proto=2202` para solicitar la información de un tile específico del mapa (por ejemplo, un castillo). Equivale a "seleccionar" un tile en la interfaz del juego. Es obligatorio enviarlo antes de cada `2452` (envío de recursos), siguiendo el patrón del juego: **seleccionar castillo → enviar recursos**. Requiere que el mapa esté abierto con `2201`; sin ese paso, el servidor desconecta al cliente.

## Wire

| Proto | Wire | Cifrado |
|-------|------|---------|
| 2202 | — | Plano |

## Payload (3 bytes)

| Offset | Tamaño | Campo | Descripción |
|--------|--------|-------|-------------|
| 0-2 | 3 | coord | Coordenada del tile a consultar, codificada en 3 bytes |

## Codificación de coordenadas

Ver [`2201.md`](2201.md#codificación-de-coordenadas-3-bytes).

## Secuencia de supply

```
Una vez (al iniciar el lote):
  1109 → 1110 (buscar perfil)
  2204 → 2205 (obtener ubicación)
  2201 (abrir mapa alrededor del target — necesario antes de 2202)

Por cada caravana:
  2202 (seleccionar castillo)
  2452 → 2453 (enviar caravana)
```

El `2201` abre el mapa una vez; después, en bucle, `2202` + `2452`. Sin el mapa abierto (2201), `2202`/`2452` pueden causar desconexión.

## Código fuente

- **Envío**: `BotInstance.sendCaravanBatch()` en `backend/src/bot/core/bot-instance.ts`

## Ejemplo

```
Coordenada del castillo destino: 16 02 ff
Proto: 2202
Body:  1602ff
```

## Notas

- El body son los mismos 3 bytes de coordenada que se usan en 2452
- El patrón del juego es: consultar tile (seleccionar castillo) → enviar recursos
- Si no se envía 2202 antes de 2452, o el mapa no está abierto (2201), el servidor kickea al cliente
- No se espera una respuesta específica del servidor; se envía 2202 y luego se procede con 2452
- Entre `2201`, `2202` y `2452` debe haber ≥1 s de separación (`waitMapProtoCooldown()`); si van pegados, el 2453 devuelve `0e` (rate limit) y la caravana no sale
