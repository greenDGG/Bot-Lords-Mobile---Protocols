# Proto 3001 — MSG_REQUEST_SENDCHAT (enviar chat)

## Wire
- Proto en el wire: `0x0BB9`

## Body
```
[[seq:4]](seq.md) - uint32 LE
[canal:1] - 0x00 = mundo/global, 0x01 = gremio
[0x00]    - 1 byte
[0x05]    - 1 byte
[len:2]   - uint16 LE, largo del texto en bytes (UTF-8)
[texto]   - len bytes
```
`9 + len` bytes en total (4 de seq + 5 + len). Sin contar el seq: `5 + len`.

## Cifrado
**DES / ECB / NoPadding** — igual que el resto de comandos con `seq`
(`sendCommandPacket(3001, body, true)` → `MessagePacket`). A diferencia del
[`3002`](3002.md), que va **plano** con `SendRaw()`.

## Detalles
- El layout es el mismo patrón que el [`3002`](3002.md): el **canal va justo
  después del seq**, sin ningún `u32` extra adelante.
- **Formato viejo (incorrecto)**: `[u32 len][u16 1][u8 5][u16 len][texto][0x0A]`.
  El servidor lo leyó como `[canal][0][5][len][texto]`, así que tomó
  `canal = 0x07` (el byte bajo del u32) y guardó de texto `00 05 01 00 6c 0a…`
  con `msgLen = 256`. Evidencia en `logs/bot_1527799837_20260809_173949.log:283-287`.
- El servidor confirma con un [`3003`](3003.md) de `count = 1`, `kind = 0x00`
  (vista gremio) y `playID` propio. En esa misma captura la vista pedida en el
  init era `kind = 0xFF` (mundo), o sea el empuje viene por el canal del mensaje.
- `canal` usa la misma numeración que el 3002/3003: `0` = mundo, `1` = gremio.
- El texto se manda tal cual en UTF-8; no lleva `\n` ni byte de cierre.

## Usos en el bot
- Comando manual `chat <texto>` → `app.gateway.ts` → `sendChat(text)` (canal
  gremio por defecto).
- Aviso automático al acabarse la energía en una caza
  (`BotInstance.announceNoEnergy()`): `Nv.<lvl> <nombre> K: <reino> X:<x> Y:<y> <hp>%`,
  con spam-guard de 5 min.

## Ejemplo
`chat hola` con seq `0x0000000F`:
```
0f000000 01 00 05 04 00 686f6c61
```
