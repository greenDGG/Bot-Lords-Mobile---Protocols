# 7315 — Agrupaciones a Fortalezas

Respuesta del servidor con la lista de guerras activas a fortalezas. Equivalente al `2478` (castillos) y `6611` (torres).

## Dirección

**Servidor → Cliente** (respuesta a `2476`)

## Payload

**Importante:** cada paquete 7315 trae **UNA sola entrada (53 bytes)**. El servidor manda las
agrupaciones una tras otra en ráfaga (paquete 1 = posición 0, paquete 2 = posición 1, ...),
no una lista concatenada.

```
Offset  Tamaño  Tipo     Campo
------  ------  -----    -----
[0-3]   4       uint32   Posición de la entrada en la lista (0, 1, 2...) — confirma
                         llegar el primer paquete de la ráfaga con 0
[4]     1       uint8    Flag de estado (00 = en espera, 01 = en marcha)
[5-8]   4       uint32   Timestamp de inicio (unix seconds, LE)
[9-12]  4       uint32   Padding (00000000)
[13-14] 2       uint16   Tiempo restante en segundos (LE)
[15-16] 2       uint16   Padding (0000)
[17-19] 3       bytes    Ubicación (3 bytes) — NO es pad ni iconType
[20-21] 2       uint16   ID del icono del atacante (LE)
[22-34] 13      string   Nombre del atacante (null-padded, 13 bytes fijos,
                         sin separador entre nombre y subType)
[35-36] 2       uint16   Sub-tipo de agrupación (ej: 0f03) ⚠ sin investigar
[37-40] 4       uint32   Tropas actuales en la agrupación (LE)
[41-44] 4       uint32   Capacidad máxima de tropas (LE)
[45-46] 2       uint16   Reino (LE, ej: cf04 = 1231)
[47-49] 3       bytes    Ubicación de la FORTALEZA (3 bytes)
[50]    1       uint8    Nivel de la fortaleza
[51-52] 2       uint16   Desconocido (0100) ⚠ sin investigar
```

## Campos

| Campo | Descripción |
|-------|-------------|
| index[0-3] | Posición en la lista; el primer paquete de la ráfaga vale 0 |
| flag | Estado de la agrupación: `01` = en marcha (atacando), `00` = en espera |
| timestamp | Unix timestamp de cuándo empezó la agrupación |
| timeRemaining | Segundos restantes (ej: 0x0015 = 21s) |
| loc[17-19] | Ubicación de 3 bytes, origen/relacionada — qué representa falta investigar |
| iconId | ID del icono del atacante |
| enemyName | Nombre del jugador que creó la agrupación (13 bytes, null-padded) |
| subType | Sub-tipo de agrupación (0f03 en ejemplo real) ⚠ sin investigar |
| troopsCurrent | Cantidad de tropas actuales (uint32 LE) |
| troopsMax | Capacidad máxima de tropas (uint32 LE) |
| kingdom | Número de reino del jugador |
| loc[47-49] | Ubicación de la fortaleza → se usa como `coordX/coordY` del grupo |
| level | Nivel de la fortaleza (1-5) |
| [51-52] | 0100, sin investigar |

Notas sobre las ubicaciones: los 3 bytes en [17-19] y [47-49] comparten los 2 primeros bytes
(`2702...` en el ejemplo), igual que en el ejemplo antiguo (`2602...` en ambas) — parece que
los 2 primeros bytes son zona y el tercero el punto.

## Diferencias con 2478 y 6611

| Característica | 2478 (castillos) | 6611 (torres) | 7315 (fortalezas) |
|----------------|------------------|---------------|---------------------|
| Header | 6 bytes | 6 bytes | Sin header fijo |
| Flag de marcha | ❌ | ❌ | ✅ `[4]` |
| Orden de campos | ts, timeRem, coords, name | ts, timeRem, coords, name | pad, flag, ts, timeRem, loc, name |
| Segundo nombre | ✅ Sí | ❌ No | ❌ No |
| Tropas/capacidad | ❌ No | ❌ No | ✅ Sí |
| Nivel | ❌ No | ❌ No | ✅ Sí |
| Reino | ❌ No | ❌ No | ✅ Sí |

## Parser actual

Implementado en `war-detector.ts → handle7315()` (línea 221).

```typescript
while (off + 35 <= payload.length) {   // 35 = bytes fijos hasta el nombre
  off += 4;                            // pad
  const inMarch = payload[off] === 0x01; off += 1;  // flag
  ...ts(4), pad(4), timeRem(2), pad(2)...
  off += 3;                            // loc[17-19] (sin determinar)
  ...iconId(2)...
  const rallyLeader = nombre(13).replace(/\0+$/, ''); off += 13;
  // subType/tropas/max/reino/loc fortaleza/nivel con bounds-check
}
```

`coordX = loc[47] | (loc[48] << 8)`, `coordY = loc[49]` → se copia a `WarEvent.inMarch` el flag.

**Acumulación en lote:** como cada paquete es una entrada, NO se reemplaza la lista.
- Se limpian las fortalezas cuando empieza un lote nuevo: `serverIndex === 0` o tras pedir `2476` (`fortressResetPending`).
- Las entradas del lote se indexan por orden de llegada: la primera = `index 0`.
- Merge por `coordX|coordY|rallyLeader` (actualiza tropas/flag/nivel/tiempo).

**Estado:** Implementado y corregido (2026-09) según análisis con hex real.

## Unirse a una fortaleza

El mecanismo es el mismo que castillos/torres:

1. Enviar `2476` (abrir guerra)
2. Recibir `7315` (lista de fortalezas)
3. Enviar `1144` acción 11 (seleccionar pestaña)
4. Enviar `1144`/`2480` con `index * 256` (seleccionar por posición)
5. Recibir `2481` (confirmación)
6. Enviar `2472` con tropas (usando nombre del enemigo)

**No hay "group ID"** — se une por posición en la lista ordenada por tiempo restante.
