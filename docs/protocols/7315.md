# 7315 — Agrupaciones a Fortalezas

Respuesta del servidor con la lista de guerras activas a fortalezas. Equivalente al `2478` (castillos) y `6611` (torres).

## Dirección

**Servidor → Cliente** (respuesta a `2476`)

## Payload

Cada entrada tiene longitud variable (~53 bytes por entrada):

```
Offset  Tamaño  Tipo     Campo
------  ------  -----    -----
[0-3]   4       uint32   Padding (00000000)
[4]     1       uint8    Separador (00)
[5-8]   4       uint32   Timestamp de inicio (unix seconds, LE)
[9-12]  4       uint32   Padding (00000000)
[13-14] 2       uint16   Tiempo restante en segundos (LE)
[15-16] 2       uint16   Padding (0000)
[17-18] 2       uint16   Tipo/bando del ícono (fijo 2602)
[19-20] 2       uint16   ID del ícono del atacante (LE)
[21-33] 13      string   Nombre del atacante (null-terminated, 13 bytes fijos)
[34]    1       uint8    Separador (00)
[35-36] 2       uint16   Sub-tipo de agrupación (ej: 0d02)
[37-40] 4       uint32   Tropas actuales en la agrupación (LE)
[41-44] 4       uint32   Capacidad máxima de tropas (LE)
[45-46] 2       uint16   Reino (LE, ej: cf04 = 1231)
[47-49] 3       bytes    Ubicación (3 bytes)
[50]    1       uint8    Nivel de la fortaleza
[51-52] 2       uint16   Desconocido (0100)
```

## Campos

| Campo | Descripción |
|-------|-------------|
| timestamp | Unix timestamp de cuándo empezó la agrupación |
| timeRemaining | Segundos restantes (ej: 0x012c = 300s = 5 min) |
| iconType | Tipo/bando del ícono (parece fijo `2602`) |
| iconId | ID del ícono del atacante |
| enemyName | Nombre del jugador que creó la agrupación (13 bytes) |
| subType | Sub-tipo de agrupación (0d02 en el ejemplo) |
| troopsCurrent | Cantidad de tropas actuales (uint32 LE) |
| troopsMax | Capacidad máxima de tropas (uint32 LE) |
| kingdom | Número de reino del jugador |
| location | Coordenadas/ubicación (3 bytes) |
| level | Nivel de la fortaleza (1-5) |

## Ejemplo real

```
Hex: 3900931c00000000 000ea4956a 00000000 2c01 0000
     2602 2d1a 0c50616e2052656c6c656e6f 00
     0d02 70820300 f0062200 cf04 2602bb 05 0100

Desglose:
- 00000000 = padding
- 00 = separador
- 000ea4956a = timestamp (0x6aa40e00 = Junio 2026)
- 00000000 = padding
- 2c01 = 300 segundos = 5 minutos
- 0000 = padding
- 2602 = tipo/bando
- 2d1a = icon ID
- 0c50616e2052656c6c656e6f = "Pan Relleno" (13 bytes con null)
- 00 = separador
- 0d02 = sub-tipo
- 70820300 = 232,000 tropas actuales
- f0062200 = 2,232,000 capacidad máxima
- cf04 = reino 1231
- 2602bb = ubicación (3 bytes)
- 05 = nivel 5
- 0100 = desconocido
```

## Diferencias con 2478 y 6611

| Característica | 2478 (castillos) | 6611 (torres) | 7315 (fortalezas) |
|----------------|------------------|---------------|---------------------|
| Header | 6 bytes | 6 bytes | Sin header fijo |
| Orden de campos | ts, timeRem, coords, name | ts, timeRem, coords, name | padding, ts, timeRem, name, troops |
| Segundo nombre | ✅ Sí | ❌ No | ❌ No |
| Tropas/capacidad | ❌ No | ❌ No | ✅ Sí |
| Nivel | ❌ No | ❌ No | ✅ Sí |
| Reino | ❌ No | ❌ No | ✅ Sí |

## Parser actual

Implementado en `war-detector.ts → handle7315()`.

```typescript
// Nombre: 13 bytes fijos null-padded, NO length-prefixed
const rawName = payload.toString('ascii', off, off + 13);
const enemyName = rawName.replace(/\0+$/, '');
off += 13;
```

## Unirse a una fortaleza

El mecanismo es el mismo que castillos/torres:

1. Enviar `2476` (abrir guerra)
2. Recibir `7315` (lista de fortalezas)
3. Enviar `1144` acción 11 (seleccionar pestaña)
4. Enviar `1144` con `index * 256` (seleccionar por posición)
5. Recibir `2481` (confirmación)
6. Enviar `2472` con tropas (usando nombre del enemigo)

**No hay "group ID"** — se une por posición en la lista ordenada por tiempo restante.

## Notas

- El campo `subType` (0d02) podría diferenciar tipos de fortaleza
- El campo `2602` en bytes 17-18 parece ser fijo (tipo/bando)
- Los campos de ubicación (3 bytes) podrían contener coordenadas comprimidas
- El campo desconocido `0100` al final podría ser flags o versión
