# Proto 2037 - Estado del Refinar Maná

## Descripción

El servidor envía `Proto=2037` para informar el estado diario del **refinar maná**: cuántas veces se reclamó el refine ese día.

**Regla simple:** el contador de reclamadas del día va en la "3ª separación" (4 bytes, `uint32` little-endian) de cada entrada del payload. Los valores vistos son `00`, `01`, `02`… hasta el máximo, que es **5**.

El reset del contador lo maneja el propio juego: tras el reset de la cuenta, el `2037` vuelve a `0` y el bot puede refinar de nuevo. **No hace falta** guardar `manaLimit` ni `reset` en la DB.

Es un paquete de **servidor → cliente** (notificación de estado).

## Wire

| Proto | Wire | Cifrado |
|-------|------|---------|
| 2037 | `0x07F5` | plano |

## Payload

El payload llega como una o más **entradas** de 40 bytes. Cada entrada tiene la misma estructura:

| Offset | Tamaño | Campo | Descripción |
|--------|--------|-------|-------------|
| 0-3 | 4 | identificador | Id del tipo / tier del refine |
| 4-7 | 4 | valor A | Costo u otro dato del refine |
| 8-11 | 4 | cero | Reservado |
| 12-15 | 4 | valor B | Timestamp / dato del servidor |
| **16-19** | **4** | **reclamados** | **`uint32` LE: cuántas veces se reclamó el refine hoy (0..5)** |
| 20-39 | 20 | ceros | Reservado |

> Lo que importa es la **3ª separación** (offset 16-19): `00` = reclamado 0, `01` = reclamado 1, `02` = reclamado 2. Máximo: `05`.

## Ejemplo

```
[RECV #90] Proto=2037 Len=44 header=2c00f507 body=
68870100c9 090000000000003f000000 000000000000000000000000000000000000000000000000
d1af000040 06000000000000c1060000 010000000000000000000000000000000000000000000000
13ac000040 06000000000000c6060000 020000000000000000000000000000000000000000000000
```

Cada línea = una entrada de 40 bytes. Leyendo la 3ª separación (offset 16):

| Entrada | bytes 16-19 | reclamados |
|---------|-------------|------------|
| 1 | `00 00 00 00` | 0 |
| 2 | `01 00 00 00` | 1 |
| 3 | `02 00 00 00` | 2 |

En el código:

```ts
const count = body.readUInt32LE(16); // 0..5
```

## Uso en el bot

- Al recibir `2037`, se cachea `refineManaCount = body.readUInt32LE(16)` (`bot-instance.ts`).
- La acción `RefineManaAction` solo refina si `refineManaCount < 5`.
- Si `refineManaCount >= 5`, loguea "máximo alcanzado" y no envía nada.
- Al refinar, el cache local se incrementa en 1 y el próximo `2037` vuelve a sincronizar el valor real.

## Vínculo con 2038 (Refinar)

`Proto=2038` es el **comando cliente → servidor** que ejecuta el refinar maná.

| Proto | Wire | Direction | Payload |
|-------|------|-----------|---------|
| 2038 | `0x07F4` | cliente → servidor | `00 01 00` (3 bytes) |

- El bot **solo envía `2038`** si el `2037` indica menos de 5 reclamados.
- Cada `2038` cuesta **10.000 de cada recurso** (trigo, madera, piedra, mineral, oro). Antes de enviarlo, el bot verifica el saldo (`hasEnough`) y, si falta, cubre el déficit con items de la bolsa (proto `1406`).
- El juego descuenta el costo y, al completarse, actualiza el `2037` con el nuevo contador.
