# Protocol 2825 / 2826 — Guild Applications (Request / Response)

**Protocol:** 2825 (request) / 2826 (response)
**Status:** Partial reverse engineering
**Last updated:** 2026-09-16

---

## Disclaimer

Fields are classified as:
- **KNOWN**: Meaning confirmed.
- **UNKNOWN**: Present but meaning not determined.

---

## Proto 2825 — Request (Client → Server)

**Size:** 4 bytes (header only, no body)

This is a ping/request from the client to ask the server for the current guild applications list. The server responds with proto 2826.

```
Header: 0400 090b
```

| Offset | Size | Type | Value | Description |
|--------|------|------|-------|-------------|
| 0 | 2 | uint16 LE | `0400` | Packet length (4 bytes) |
| 2 | 2 | uint16 LE | `090b` | Protocol number (2825) |

## Proto 2826 — Response (Server → Client)

**Size:** 4 + 3 + (43 × N) bytes, where N = number of applications

### Header

| Offset | Size | Type | Value | Description |
|--------|------|------|-------|-------------|
| 0 | 2 | uint16 LE | `5d00` (example) | Packet length |
| 2 | 2 | uint16 LE | `0a0b` | Protocol number (2826) |

### Body

| Offset | Size | Type | Value | Description |
|--------|------|------|-------|-------------|
| 0 | 2 | uint16 LE | `0001` | Version (always 1 in observed packets) |
| 2 | 1 | uint8 | count | Number of applications in the list |

## Open Questions

1. **What is the 2-byte unknown field at +8?**
   Varies per user (34 vs 29). Could be player level, kingdom ID, or application timestamp. Needs more captures.

2. **What is the version field (`0001`)?**
   Always `0001` in observed packets. Could be protocol version. If the server upgrades this field, the per-user entry format may change.

3. **What are the 7 trailing zero bytes at +36?**
   Always zero. Could be reserved for future fields, or padding to align entries.

4. **Can the application list be empty (count = 0)?**
   Not observed. The packet would be 5 bytes (header + version + count). Needs testing.
