# Proto 5205 - Coliseo (respuesta de rivales)

## Descripción

El servidor envía `Proto=5205` como respuesta a [`5204`](5204.md) con la lista actualizada de rivales del Coliseo.

## Wire

| Proto | Wire | Cifrado |
|-------|------|---------|
| 5205 | `0x1455` | plano |

## Payload (cabecera)

| Offset | Tamaño | Campo | Descripción |
|--------|--------|-------|-------------|
| 0-3 | 4 bytes | flags | `04 00 01 00` — desconocido (posible contador o flags) |
| 4-13 | 10 bytes | desconocido | Datos del jugador actual (sin decodificar) |

## Payload (rivales, desde offset 14)

Mismo formato que el body de [`5201`](5201.md):

| Campo | Tamaño | Descripción |
|-------|--------|-------------|
| nombre | ASCII hasta `00` (padding nulo) | Nombre del rival |
| tag de gremio | 3 bytes ASCII | Tag del gremio |
| bloque héroe | 36 bytes | `heroId` (4, `uint32` LE) + 16 × `uint16` (datos de héroes) |

## Comparación con 5201

| | 5201 | 5205 |
|--|------|------|
| Header size | 30 bytes | 14 bytes |
| Campos header | rank, peleas, gemas, unknown | flags + datos jugador |
| Rivals start | offset 30 | offset 14 |
| Bloque rival | idéntico | idéntico |

## Uso en el bot

- Se parsea con `parseColiseumRivals(body)` (`backend/src/models/coliseum.ts`).
- Actualiza `coliseumState.rivals` conservando rank/fightsDone/gems del último `5201`.
- Se emite `coliseumUpdated` para refrescar la UI.
