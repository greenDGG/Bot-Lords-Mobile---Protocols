# Proto 9865 - Respuesta del canje (LUCKYCARD_EXCHANGE)

## Descripción

Paquete **servidor → cliente** que confirma (o rechaza) el canje enviado con el
[`9864`](9864.md). Trae el **eco del número canjeado** y el **saldo total de
gems** del jugador después del canje.

Nombres del cliente de referencia: `_MSG_RESP_LUCKYCARD_EXCHANGE`
(`Protocol.cs:1715`).

## Wire

| Proto | Wire | Cifrado |
|-------|------|---------|
| 9865 | `0x2689` | Plano (S→C) |

Header observado: `0e008926` = len 14 + proto → body de **10 bytes**.

## Payload (10 bytes)

| Offset | Tamaño | Campo | Descripción |
|--------|--------|-------|-------------|
| 0 | 1 | status | `00` = canje aplicado; otro = rechazado |
| 1-4 | 4 | echo | u32 LE: número que el servidor entendió que se canjeó |
| 5-8 | 4 | gemsTotal | u32 LE: **balance TOTAL de gems** del jugador tras el canje (no es la recompensa) |
| 9 | 1 | tail | byte final (`04` en la única muestra; sin resolver) |

## Ejemplo real (captura del usuario)

```
hex: 0e00892600da0300009338000004
     └len┘└proto┘└────── body 10 B ──────┘

body: 00 da030000 93380000 04
      │  └─ 986 ─┘ └14483──┘ └?
      status = 00 (ok)
```

```json
{ "status": 0, "echo": 986, "gemsTotal": 14483, "tail": 4 }
```

El jugador enviaba el número **986** y su saldo total de gems era **14483** al
momento del canje (confirmado por el usuario: es el saldo, no la recompensa).

## Uso en el bot

```typescript
// backend/src/bot/handlers/lucky-card.handler.ts
handle9865(bot, body);   // registrado en handlers/index.ts

// backend/src/bot/core/bot-instance.ts
onLuckyExchangeResponse(res, body);
markLuckyExchanged(reason, status, value, gemsTotal);   // cierra el evento en la DB
```

Flujo — **sólo se acepta si hay un `9864` pendiente para el evento vigente** (un
`9865` huérfano o de otra ronda se ignora con log `[CARTA] 9865 sin canje
pendiente — se ignora (<hex>)` / `[CARTA] 9865 de otro evento — se ignora`):

1. `echo === luckyExchangeSentValue` → si no coincide se loguea
   `[CARTA] 9865 eco distinto al enviado — se marca igual (status 0)`.
2. **Cualquier respuesta cierra el evento** (sólo existe UN canje por evento, no
   hay un segundo canje posible):
   - `status === 0` → `markLuckyExchanged('¡CANJE CONFIRMADO! (9865 status 00)', 0, echo, gemsTotal)`.
   - `status !== 0` → `markLuckyExchanged('9865 rechazado (status=0x..) — sólo
     existe un canje, se cierra el evento', status, echo, gemsTotal)`: si el
     servidor no da nada, capaz ya se canjeó antes, así que también se cierra.
   - sin poder parsear → se cierra con `status = -2`.
3. `markLuckyExchanged()` escribe en la DB (upsert sobre `(iggId, eventKey)`):
   `reclaimed: true`, `status`, `value`, `gemsTotal`, `at`, y los datos del
   evento (`eventStartTs`, `eventDuration`, `eventEndTs`). Además pone en
   memoria `luckyExchangeReclaimed = true` y emite `luckyCardUpdated`. Si la DB
   está caída, el estado queda en memoria y se reintenta en el próximo 9861.

También cierra el evento:

- **Sin respuesta**: si pasan los 3 intentos (`LUCKY_EXCHANGE_MAX_ATTEMPTS`)
  con timeout de 15 s, se cierra con `status = -1` (valor enviado en `value`).
- **Fallback por `9861`**: si después de mandar el `9864` llega un `9861` con
  `cardCount = 0`, se cierra con `status = 0` sin depender del timeout de 15 s.
- Si el `9864` **ni siquiera salió** (error de envío), NO se cuenta como
  intento ni se cierra el evento: se reintenta.

## Persistencia (`LuckyExchangeClaim`)

| Campo | Contenido |
|-------|-----------|
| `eventKey` | `${eventStartTs}_${eventDuration}` = `1790485200_172740` (hash único del evento) |
| `eventStartTs` / `eventDuration` / `eventEndTs` | bytes 0-3 y 8-11 del `9861`; fin = inicio + duración |
| `reclaimed` | `true` en cuanto se cierra el evento: no volver a buscar ni a canjear |
| `status` | `0` = ok · `>0` = status del `9865` · `-1` = sin respuesta · `-2` = `9865` sin parsear · `-3` = migración desde `exchangedTs` |
| `value` | número enviado en el `9864` |
| `gemsTotal` | saldo total de gems que trajo el `9865` (0 si no hubo confirmación) |
| `at` | unix s en que se cerró |

Índice único `(iggId, eventKey)`: una fila por cuenta y por evento.

**Migración**: las cuentas con `config.luckyCards.exchangedTs` igual al inicio
del evento vigente (en la DB o en su `access/<id>/config.json`) se siembran en
la DB con `status = -3` en el primer `9861`, para no volver a canjear.

## Notas

- Sólo existe **una muestra** de este paquete (canje de 986), así que `tail` y el
  comportamiento ante `status != 0` están observados pero no probados en vivo
  (en los logs todavía no aparece ni un `9864` ni un `9865` disparado por el bot).
- El bot **no** descuenta ni recalcula gems: sólo loguea `gemsTotal`.
- Si llega sin poder parsear (< 6 bytes) se registra crudo y cierra el evento:
  `[CARTA] 9865 sin parsear (N B): <hex>`.
